# `tsconfig.tsbuildinfo` — Documentation

> **File location:** `frontend/tsconfig.tsbuildinfo`

---

## 1. File Role

### What is this file?

`tsconfig.tsbuildinfo` is a **build cache file automatically generated by TypeScript**.

When you run `tsc -b` (the TypeScript build command used in `npm run build`), TypeScript
checks all your source files for type errors. After it finishes, it saves a summary of
what it checked and what it found into this file.

The next time you run `tsc -b`, TypeScript reads this file first. If a source file has
**not changed** since the last build, TypeScript skips re-checking it and uses the cached
result. This makes subsequent builds **much faster**.

> ⚠️ **You should never edit this file manually.** It is automatically created, read,
> and updated by the TypeScript compiler. Its content is not meant to be human-readable.

### Why is it important?

Without this file, TypeScript would re-check every single file from scratch on every build —
even files you have not touched. For large projects with many files, this would make
`npm run build` very slow.

With this file, TypeScript only re-checks files that have **actually changed**, making
incremental builds much faster.

---

## 2. Code Explanation (Key Fields)

The file contains a single large JSON object. Most of its content consists of
cryptographic hashes and internal compiler state. Here are the meaningful fields:

---

### `"root"` — The Files TypeScript Checked

```json
"root": [
  "./src/app.tsx",
  "./src/main.tsx",
  "./src/vite-env.d.ts",
  "./src/app/router.tsx",
  "./src/app/guards/protectedroute.tsx",
  "./src/app/guards/roleroute.tsx",
  ...
]
```
→ This is the list of **all TypeScript source files** that were included in the last
type-check run.

Notice the paths use lowercase (e.g. `"./src/app.tsx"` instead of `"./src/App.tsx"`).
This is because the build info stores paths in a normalised (lowercase) form for
cross-platform compatibility — file systems on Windows are case-insensitive, while
Linux is case-sensitive.

---

### `"version"` — TypeScript Compiler Version

```json
"version": "5.9.3"
```
→ Records which version of the TypeScript compiler generated this file.

If you update TypeScript to a new version, the compiler detects that the version
no longer matches and automatically invalidates the cache, forcing a full re-check.
This prevents stale cache results from hiding type errors introduced by a new TypeScript version.

---

### Other Internal Fields (Not Listed)

The rest of the file contains:
- **File content hashes** — a fingerprint of each file's content. If the file changes,
  the hash changes, and TypeScript knows to re-check that file.
- **Type resolution state** — how TypeScript resolved imports between files.
- **Diagnostic results** — whether each file passed or failed type checking last time.

These are machine-readable only and have no practical meaning when read by a human.

---

## 3. Concepts

### 🔹 Incremental Compilation

Without a build cache:
```
You change 1 file out of 50 → TypeScript checks all 50 files
```

With incremental compilation (`.tsbuildinfo`):
```
You change 1 file out of 50 → TypeScript checks only that 1 file
```

This is a huge time saving in large projects.

---

### 🔹 How TypeScript Uses This File

The process works like this:

1. **First run:** `tsc -b` checks all files, creates `tsconfig.tsbuildinfo`.
2. **You edit one file.**
3. **Next run:** `tsc -b` reads `tsconfig.tsbuildinfo`, sees which files changed
   (by comparing hashes), re-checks only those files, and updates the `.tsbuildinfo` file.

---

### 🔹 The `-b` Flag

`tsc -b` (build mode) is what makes TypeScript use and update the `.tsbuildinfo` file.
Without `-b`, TypeScript does a regular full check and does not write any cache file.

In `package.json`:
```json
"build": "tsc -b && vite build"
```

`tsc -b` runs first to check types (and uses the cache). If there are no errors,
`vite build` runs to bundle the code for production.

---

### 🔹 Should I Commit This File to Git?

**Generally no** — but this project includes it.

**Reasons NOT to commit it:**
- It is a generated file that changes with every build.
- It adds noise to commits and code reviews.
- Each developer's machine will generate their own version.

**Reasons to commit it (as done here):**
- CI/CD pipelines can reuse the cache from the previous build, speeding up CI.
- It documents the last known good TypeScript compiler version used.

Common practice is to add it to `.gitignore`, but both approaches are valid.

---

## 4. Summary

`tsconfig.tsbuildinfo` is an automatically generated build cache file created by the
TypeScript compiler. It:

1. Is generated when you run `tsc -b` (which happens during `npm run build`).
2. Records which files were checked and a fingerprint (hash) of each file's content.
3. Allows TypeScript to skip re-checking unchanged files on the next build.
4. Makes repeated `npm run build` calls faster by only re-checking what changed.
5. Records the TypeScript compiler version — if you upgrade TypeScript, the cache is automatically invalidated.
6. Should **never be edited manually**.

Think of it as TypeScript's "notes from the last exam" — it remembers what it already
checked so it only reviews what's new next time.
